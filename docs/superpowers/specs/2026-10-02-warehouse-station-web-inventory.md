## Завершение заказа и печать

### Кнопка «🏁 ЗАВЕРШИТЬ ЗАКАЗ» (`app_finish.py`, кнопка `app_layout.py:299`)

Активна, когда отсканированы все блоки последней позиции (`app_scanning.py:477-483, 609, 731-765`);
выключается при отмене кода, пока позиция не добрана, на время операций и при блокировке обновлением

Ошибки оператор видит через `show_error` (`app_runtime.py:305`), модального окна нет:
- строка статуса «❌ {текст}» на красном фоне 5000 мс (`STATUS_NOTICE_TIMEOUT_MS`), потом «✅ Готов к работе»
- красный toast над статусом
- в метке последнего кода «Ошибка: {текст}»
- `show_critical_error(title, exc)` показывает «{title}: {message}» так же и шлёт Telegram-алерт администраторам
  (в веб-копии алерт шлёт сервер, решение в спецификации)

Этап 2, завершение на сервере (`complete_work`, строки 145-185):
1. `sync_pending_backend_events` досылает сканы заказа и его `order_complete`
2. `backend_sync_group_blocker` (`backend_flow.py:198-213`):
   - обрыв связи: завершение ставится в очередь, текст «Сводный лист напечатан. Связь с сервером прервалась.
     События заказа сохранены в очереди: N. Отправятся автоматически, когда связь вернётся» (`backend_flow.py:139-164`)
   - отказ сервера по сканам: «Сводный лист напечатан, но backend не принял все КИЗы. {blocker}», где blocker
     «Backend не принял события текущего заказа. Осталось по заказу: N. {последняя ошибка}»; завершение в очередь не ставится
3. `complete_backend_orders_or_raise` (`backend_flow.py:257-279`) по каждому заказу группы: событие `order_complete`
   в очередь (сбой: «Не удалось сохранить завершение заказа в локальную очередь backend.»), затем
   `POST /api/v1/orders/{id}/complete`, ответ «already completed» и аналоги считается успехом (`backend_flow.py:228-246`),
   при успехе событие удаляется
4. backup JSONL `scan_backups/scan_backup_dd.mm.yyyy.jsonl` (сбой: «Сводка напечатана, но backup завершения заказа не создан»)

Итог этапа 2:

Группа исчезает из списка сразу после печати, окончательно освобождается первым обновлением списка после ответа

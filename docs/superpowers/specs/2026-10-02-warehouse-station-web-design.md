# Склад в браузере: точная копия программы на chapman.taksklad.uz/

Дата: 2026-10-02
Статус: замысел согласован с Антоном в чате 02.10, спецификация на просмотре
Опись окон программы для сверки: [2026-10-02-warehouse-station-web-inventory.md](2026-10-02-warehouse-station-web-inventory.md)

## Задача

Слова Антона (чат 02.10):

1. Сделать сайт, который выглядит и работает один в один как Windows-программа склада:
   расцветка, кнопки, их расположение, окна, чтобы склад не переучивался
2. Сайт работает без логина и пароля и всегда доступен
3. Сайт, а не программа, потому что сайт обновлять легче
4. Открывается только из сети склада
5. Печать без окна печати, через ярлык Chrome с тихой печатью
6. Переносится вся программа, не только экран КИЗ
7. Адрес `https://chapman.taksklad.uz/`

Допущения, подтверждённые Антоном одобрением замысла 02.10:

- «вся программа» значит всё, что кладовщик видит на экране: главное окно, «Коды позиции»,
  «КИЗ занят», «Параметры печати», «Возвраты» с подтверждением, «Закрыть смену»,
  «Диагностика», «Очереди»
- окна импорта, справочника и панели контроля есть в коде программы, но кнопок на экране
  у них нет, поэтому не переносятся; окна обновления и подключения сайту не нужны
- программа остаётся на складском ПК рядом, пока склад не отработает на сайте и Антон
  не решит её убрать

## Что считается успехом

1. Кладовщик открывает ярлык на складском ПК и без пароля попадает в окно, которое
   выглядит и ведёт себя как главное окно программы
2. Все действия программы, которые видит кладовщик, есть на сайте с теми же текстами,
   кнопками и порядком шагов
3. Лист печатается сам, без окна печати, на тот же принтер и того же размера
4. При обрыве интернета сканирование продолжается, коды и завершения уходят сами
   после восстановления связи
5. Из-за пределов сети склада экран станции не открывается, а вход станции, вынесенный за пределы склада,
   не работает; это закрывает интерфейс станции, данные склада по-прежнему открыты ключом программы (раздел 8)
6. Пилот проходит по критериям раздела 10: ноль расхождений КИЗ, полные завершения, один лист на заказ

## Решение

### 1. Устройство

Новый вид `station` внутри существующего SPA (`frontend/src/station/`)
Выбор вида по пути: `/admin` и ниже панель управления, всё остальное станция
(`frontend/src/workspace/surface.ts`)
Станция собирается одной частью сборки и целиком подгружается при открытии, без ленивых кусков по окнам:
после выкатки открытая станция не должна просить файлы, которых на сервере уже нет
Старый операторский экран на `/` больше не монтируется; его переиспользуемые модули
(офлайн-очередь, `kizFormat.ts`, `scanQuantities.ts`, клиент API) станция берёт как есть,
удаление остального кода старого экрана отдельным PR после пилота

Загрузка `/`:
1. `GET /api/v1/auth/session`
2. сессия есть и роль `station`: экран станции
3. сессия есть и роль другая: переход на `/admin`
4. сессии нет: `POST /api/v1/auth/station`
   - успех: экран станции
   - 403 с кодом `station_network_denied`: переход на `/admin`
   - сеть недоступна, 5xx, 429: экран станции без связи, как программа при старте без сети
     («Список заказов пока не загружен: …»), повтор входа по таймеру

Одна станция на окно браузера: блокировка Web Locks на очередь и печать; второе окно показывает
«Станция уже открыта в другом окне» и ничего не отправляет (программа так же не даёт открыть вторую копию,
`main.py:194`)

### 2. Доступ: складской вход по сети склада

Backend:
- переменная `TAKSKLAD_WAREHOUSE_CIDRS`, список через запятую; пустая значит станция выключена и вход всегда отказ;
  битое значение, `0.0.0.0/0`, `::/0` и частные диапазоны не роняют backend, а выключают станцию с записью в журнал;
  в `deploy/vds/docker-compose.yml` с пустым значением по умолчанию; смена списка требует пересоздания `backend-api`
- новая роль `station` (`backend/app/access_policy.py`, `normalize_role` в `backend/app/web_auth.py:176`)
  с правами `warehouse:read`, `warehouse:write`, `reports:read`; без `admin:*`, `imports:*`, `client_points:*`
  `reports:read` нужен для `GET /api/v1/reports/day` и открывает ещё чтение КИЗ-отчётов
  (`/api/v1/reports/kiz/*`, `/api/v1/reports/reconciliation/day`); принимаем, вход только из сети склада
- пользователь станции `warehouse-station`: роль `station`, `password_hash` пустой, имя не из цифр,
  поэтому парольный вход для него невозможен (`backend/app/web_auth.py:68, 160`); создаётся при первом успешном
  входе станции вставкой с `ON CONFLICT DO NOTHING`, миграция не нужна (`users.role` строка без CHECK)
- `POST /api/v1/auth/station`, публичный (`_public()`): проверка Origin как у входа (`require_browser_origin`);
  сначала адрес клиента из `client_identity` (`backend/app/main.py:674`) сверяется со списком, промах даёт 403
  `station_network_denied` без записи в общий ограничитель входа (`main.py:225`), чтобы чужие попытки
  не забивали и не блокировали вход в `/admin`; успешные входы станции ограничены своим счётчиком
  (не больше 10 в минуту с адреса); успех создаёт сессию пользователя станции тем же путём и с той же cookie,
  что вход (`main.py:603-664`), и отдаёт `csrf_token`
- проверка на каждом запросе: `read_web_session` (`main.py:586-600`) после `validate_user_session`
  для роли `station` сверяет адрес клиента со списком и при промахе отвечает как на невалидную сессию;
  все читатели cookie (`read_auth_context`, `/auth/session`, `/auth/check`, `/auth/logout`) идут через неё;
  для других ролей поведение не меняется
- отзыв: `users.is_active = false` у пользователя станции мгновенно гасит все её сессии
  (`auth_state_digest`), пустой список адресов закрывает новый вход

Путь адреса клиента, проверено на сервере 02.10:
- traefik не доверяет входящему `X-Forwarded-For` (в `deploy/traefik/docker-compose.yml` нет `forwardedHeaders.trustedIPs`)
  и пишет адрес клиента сам
- `vds-frontend-1` и `vds-backend-api-1` стоят в двух сетях: `traefik` `172.18.0.0/16` и `vds_taksklad-internal`
  `172.22.0.0/16`; nginx сейчас получает `backend-api` как `172.18.0.4`, то есть доверенный адрес, но выбор сети
  делает DNS Docker, а не настройка; если соединение пойдёт через `172.22`, backend увидит адрес nginx вместо склада
- поэтому nginx ходит в backend по сетевому псевдониму, заведённому только в сети `traefik`
  (`deploy/vds/docker-compose.yml`, `aliases` у `backend-api`), а не по имени сервиса
- в `frontend/nginx.conf.template` в `location /api/` и в `location = /_taksklad_auth_check` одинаково
  `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for` и `X-Real-IP $remote_addr`
- новый `location = /api/v1/auth/station` без `auth_request`, по образцу `/api/v1/auth/login`
- остаточный риск: любой контейнер в сети `traefik` доверенный и может подставить свой `X-Forwarded-For`;
  так же сейчас устроен ограничитель входа, менять это вне работы

Склад как рабочие места: один пользователь станции на все ПК склада; ПК различаются полем
`workstation_id` в сканах, имя ПК задаётся в ярлыке параметром `?station=<имя>` и запоминается в браузере,
без параметра `web-station`; `actor` в отмене и освобождении КИЗ `station`

Смена адреса склада посреди смены: запросы станции получают 401, очередь держит коды (401 для неё повторяемая
ошибка, `frontend/src/features/warehouse/offline/errorPolicy.ts`), строка статуса показывает
«⛔ Станция не опознала сеть склада. Коды сохраняются, работайте в программе и сообщите администратору»;
новый вход станция пробует не чаще раза в 30 секунд

### 3. Экраны и точность

Каждое окно и каждая кнопка из описи переносится с теми же текстами, цветами, шрифтами, размерами
и условиями включения; опись по модулям в файле описи

| Программа | Станция |
|---|---|
| `app_layout.py`, `ui_widgets.py` | главное окно, кнопка `AppButton` |
| `order_list_widgets.py`, `order_list_models.py` | список заказов с датами, поиском, клавишами |
| `app_order_display.py`, `product_images.py` | текущая позиция, фото товара и GTIN |
| `app_scanning.py`, `desktop_scan_rules.py`, `scan_quantities.py`, `utils.validate_kiz_code`, `kiz_blocklist.py` | правила скана, чистый модуль TS без интерфейса |
| «Коды позиции», «КИЗ занят» (`app_scanning.py`) | окна поверх главного |
| `app_finish.py`, `app_printing.py`, `printing.py`, `pending_store.py` | завершение, «Параметры печати», лист, очередь печати |
| `app_returns.py` | «Возвраты TakSklad», «Подтвердить возврат» |
| `app_day_end.py` | «📊 ЗАКРЫТЬ СМЕНУ» |
| `app_runtime.py`, `desktop_diagnostics.py` | «Очереди синхронизации», «ДИАГНОСТИКА», строка статуса, тост, закрытие окна |

Правила точности:
- цвета берутся из `src/taksklad/config.py:264-277` и дополнительных цветов в `app_layout.py`,
  `order_list_widgets.py`; один файл токенов станции
- шрифт `"Segoe UI"`, размеры в `pt` ровно как в кортежах Tk; размеры и отступы Tk в пикселях
  переносятся в `px`; Chrome масштабирует страницу по масштабу Windows; если окно программы на снимке
  с ПК склада крупнее или мельче страницы, общий коэффициент подбирается по снимку один раз для всей станции
- размер сверяется по области страницы `1250x780`, как клиентская область окна программы, а не по размеру окна с рамкой
- эмодзи в текстах рисуются одноцветными шрифтом `"Segoe UI Symbol"`, как в Tk, а не цветными
- кнопка как `AppButton` (`ui_widgets.py:41-190`): скругление 16 (у «✅ ВЫБРАТЬ ЗАКАЗ» 22), высота не меньше 38 px,
  при наведении цвет сдвигается на 10% к белому (`fade_hex`), выключенная рисуется `#e0d7b9` и `#8f8878`,
  срабатывает на нажатие мыши, фокус клавиатурой не берёт
- окна программы (Toplevel) становятся окнами внутри страницы того же размера, с нарисованной рамкой
  и заголовком как у окна Windows, по центру главного, перетаскиваются за заголовок;
  модальные блокируют главное окно, как в программе
- вопросы `messagebox.askyesno` («Сводный лист уже напечатан», «Непечатанные сводки», «Внимание»)
  рисуются как окно вопроса Windows с теми же заголовком, текстом и кнопками «Да» и «Нет», по умолчанию та же кнопка
- поля ввода без автозаполнения и проверки орфографии (`autocomplete="off"`, `spellcheck="false"`)
- звук отказа `self.bell()` заменяется коротким сигналом через Web Audio; звук включается первым кликом
  оператора, до скана он всегда есть («✅ ВЫБРАТЬ ЗАКАЗ»)
- клавиши браузера, которых в программе нет, перехвачены: F5, Ctrl+R, Ctrl+P; закрытие окна при неотправленных
  кодах вызывает общий вопрос браузера «Покинуть сайт?» вместо «Закрыть программу?» (`app_runtime.py:482-487`)

Сторожа точности:
- тест паритета цветов: токены станции против констант `config.py`, чтение исходника Python
- тест паритета текстов: каждая строка интерфейса станции находится дословно в `src/taksklad/`,
  кроме перечня согласованных отличий (раздел 7)
- правила скана гоняются общим корпусом в Python и TS, как уже сделано для формата КИЗ
  (`tests/test_kiz_format_contract.py`)
- блоклист КИЗ в станции хранится хешами SHA-256, а не кодами: статика открыта всем, проверка адреса её не закрывает;
  тест сверяет хеши с `src/taksklad/kiz_blocklist.py`

Эталон внешнего вида: снимки каждого окна с самого складского ПК; вместо живой Windows-программы
агент сверяется с этими снимками и с кодом, свою отрисовку Tk под Linux эталоном не считаем,
в ней нет Segoe UI; это не даёт попиксельной сверки на настоящем экране, её даёт приёмка на складе
Внешний вид одобряет Антон отдельно, по снимкам «программа и сайт рядом», до выкатки этапа на склад

Где код и снимок расходятся, прав снимок: копируется то, что видит склад
Это не формальность: кнопка `AppButton` просит 378 px ширины, и на окне `1250x780` ряд из четырёх кнопок
под текущей позицией по коду не помещается (на стенде две последние кнопки сжаты до 1 px), а окно просит
около 1100 px высоты, так что строки статуса и версии уходят за край; что видит склад, зависит от монитора
и того, развёрнуто ли окно; поэтому вёрстка главного окна начинается только после снимков с ПК склада,
вход станции, правила скана и логика от снимков не зависят и начинаются сразу (опись, раздел «Ловушки»)

Особенности программы:
- видимые и безвредные копируются как есть: заголовок даты «БЕЗ» вместо «Без даты», обрезка низа листа
  на этикетках 75x50 и 58x40, «Стр. 1 из 1» на одностраничном листе
- ведущие к потере или порче данных не копируются, а исправляются и перечисляются Антону: в «Кодах позиции»
  код, уже доставленный на сервер циклом очереди, программа может показать «в очереди» и при отмене убрать
  только локально, оставив скан на сервере; станция берёт состояние «сохранён» из факта доставки

### 4. Без интернета

- как в программе, скан сначала ложится в очередь, а на сервер уходит циклом каждые 15 с, при ручном
  обновлении, при «➡️ СЛЕДУЮЩАЯ ПОЗИЦИЯ» и при завершении; очередь IndexedDB уже есть (#110, #116),
  станция ставит в неё и завершения заказа (`order_complete`), как программа
- список заказов держится в памяти страницы, как в программе: после перезапуска без связи программа
  показывает «Список заказов пока не загружен», станция тоже; вчерашний список из кэша не показывается,
  заказы могли закрыть на другом ПК
- service worker держит оболочку станции (страница и собранные файлы), чтобы окно ярлыка открывалось без связи;
  навигация сначала в сеть, в кэш только при сетевой ошибке; ответ не `ok` (404, 502 при выкатке) в кэш
  не пишется и вместо кэша не отдаётся; запросы `/api/` и путь `/admin` service worker не трогает
- очередь непечатанных листов и журнал сканов (аналог `scan_backups/*.jsonl`, хранение 30 дней) в IndexedDB
- хранилище запрашивается постоянным (`navigator.storage.persist()`); если браузер отказал, строка статуса
  при старте предупреждает «⚠ Браузер может очистить очередь при нехватке места»; журнал и очередь скачиваются
  файлом из «ДИАГНОСТИКА»
- после возврата связи при истёкшей сессии станция берёт новую через `/auth/station` (не чаще раза в 30 с)
  и досылает очередь; 401 очередь уже считает повторяемой ошибкой
- список заказов грузится целиком страницами по курсору сервера (`X-TakSklad-Next-Cursor`),
  как программа, без молчаливого среза на 200

### 5. Печать

- лист рисуется на canvas с теми же координатами, шрифтами Arial и размерами, что `printing.py:357-494`,
  в 203 dpi, страница за страницей; все особенности листа сохраняются один в один,
  включая обрезку низа на 75x50 и 58x40
- печать: страницы картинками во всю этикетку, `@page { size: Wmm Hmm; margin: 0 }`, картинки декодируются
  до вызова (`img.decode()`), затем `window.print()`; конец печати по событию `afterprint`;
  ярлык Chrome с `--kiosk-printing` печатает без окна
- порядок как в программе: запись в очередь печати, печать, удаление из очереди, потом сервер
- «Параметры печати» как в программе; в поле «Принтер:» одно значение «Термопринтер»: в программе
  оно и так значит «принтер по умолчанию» (`printing.py:206`); размер этикетки и галочка
  «Запомнить параметры» работают как в программе, настройки хранятся в браузере
- браузер не сообщает, напечатал ли принтер; программа узнаёт не больше: `PrintDocument.Print()` тоже
  только отдаёт задание очереди Windows; разница одна, ошибку «принтер не найден» программа видела, станция нет
- печать вызывается только по нажатию «ПЕЧАТАТЬ» или Enter в «Параметры печати», никогда из эффекта или таймера;
  контракт `tests/test_frontend_print_contract.py` расширяется на модуль печати станции с тем же запретом автопечати

Ярлык на складском ПК:
- отдельный профиль Chrome (`--user-data-dir=<папка станции>`): без него ярлык при уже открытом Chrome
  передаёт адрес в работающий процесс и `--kiosk-printing` не действует; заодно cookie и очередь станции
  отделены от остального браузера
- `--app=https://chapman.taksklad.uz/?station=<имя ПК> --kiosk-printing`, размер окна по области страницы `1250x780`
- принтер: в профиле станции один раз печатается лист через обычное окно печати с выбором термопринтера
  и размера; дальше `--kiosk-printing` берёт запомненные Chrome принтер и настройки; если Chrome на этом ПК
  берёт принтер Windows по умолчанию, термопринтер ставится по умолчанию и выключается
  «Разрешить Windows управлять принтером, используемым по умолчанию»; тогда остальные программы этого ПК
  тоже печатают на термопринтер, это решает Антон на месте
- работает ли размер из `@page` на этом драйвере, проверяется первым же листом; если драйвер размер игнорирует,
  размер выставляется в настройках принтера, а выбор размера в «Параметры печати» перестаёт влиять на печать
  (пункт 1 раздела 7)
- лишняя пустая этикетка после листа (страница ровно в размер этикетки) ловится тестом: Playwright `page.pdf`
  с `preferCSSPageSize` даёт ровно столько страниц, сколько `tests/test_printing.py`

### 6. Обновление сайта

- сборка получает версию аргументом образа (`frontend/Dockerfile`, `tools/build_release_images.sh`) и кладёт её
  в `version.json`; nginx отдаёт `index.html`, `version.json` и файл service worker с `Cache-Control: no-cache`,
  отсутствующие `version.json` и `sw.js` дают 404, а не `index.html`
- станция спрашивает `version.json` раз в 5 минут (`cache: "no-store"`) и перезагружается на новую версию
  только в простое: заказ не выбран, нет операции и открытых окон
- строка версии внизу главного окна показывает версию сайта

### 7. Отличия от программы, на которые нужно согласие

1. Принтер выбирается в Chrome или Windows один раз, в «Параметры печати» одно значение «Термопринтер»;
   если драйвер не берёт размер со страницы, выбор размера в окне не влияет на печать
2. Окна поверх главного нарисованы внутри страницы, рамка похожа на Windows, но это не окно системы
3. Заголовок главного окна рисует Chrome
4. Звук отказа другой
5. «📊 ЗАКРЫТЬ СМЕНУ» не закрывает окно через 5 секунд: браузер не даёт странице закрыть окно ярлыка;
   итог остаётся в строке статуса
6. «ДИАГНОСТИКА» сохраняет файл в «Загрузки», пробы DNS и GitHub не делаются, проба сервера идёт
   через `/api/v1/auth/session`, а не `/health` (через фронт `/health` отдаёт страницу)
7. Telegram-алерт администраторам при критической ошибке не отправляется: браузер не держит
   ключ бота; отдельная серверная отправка это новый тип сообщения и отдельное согласование
8. Нет окна обновления
9. Станция не вызывает `POST /api/v1/sync/sources`: для сессии сайта он требует `admin:write`
   (`backend/app/access_policy.py:148`), а SkladBot и так сверяет сервер раз в минуту; поэтому после обновления
   списка статус «✅ Список заказов обновлён из backend» без варианта «SkladBot найдено {N}»
10. В сообщении о несовпадении товара строки «Версия приложения: 2.0.56» и «Если SKU на блоке верный, закройте
    приложение и запустите обновленный TakSklad.exe.» относятся к программе; на сайте предлагается версия сайта
    и «Если SKU на блоке верный, обновите страницу (F5).»
11. Строка версии: «Версия: {версия сайта} · актуальная · ПК {имя станции}» вместо хеша ПК и состояний обновления программы
12. Новые строки, которых в программе нет: «Станция уже открыта в другом окне»,
    «⛔ Станция не опознала сеть склада. Коды сохраняются, работайте в программе и сообщите администратору»,
    «⚠ Браузер может очистить очередь при нехватке места»
13. Закрытие окна с неотправленными кодами спрашивает общим окном браузера «Покинуть сайт?»
14. Код, уже доставленный на сервер, в «Кодах позиции» помечен «сохранён» и отменяется на сервере
    (в программе возможна только локальная отмена, раздел 3)

### 8. Безопасность

| Угроза | Защита |
|---|---|
| станцию открывают не со склада | вход станции только с адресов склада, остальным переход на `/admin` |
| подделка адреса заголовком снаружи | traefik не доверяет входящему `X-Forwarded-For`; backend берёт правый недоверенный адрес; тест и живая проверка |
| backend видит адрес nginx вместо склада | nginx ходит в backend только через доверенную сеть `traefik` по псевдониму |
| cookie станции унесли со склада | каждый запрос станции сверяется с адресами склада |
| станция делает лишнее | роль без админских прав, импортов и точек клиентов |
| межсайтовые запросы | действующие Origin и CSRF для сессий сайта |
| перебор входа станции | отказ без состояния, успешные входы ограничены 10 в минуту с адреса |
| гость в сети склада | откроет станцию, как сейчас может поставить программу; закрывается отдельной сетью для гостей на складе |

Станция закрывает только свой интерфейс, а не данные: ключ программы по-прежнему выдаётся любому
(`POST /api/v1/auth/desktop-bootstrap` и самоподтверждение через `/api/v1/auth/desktop-pairing/{id}/ack`,
`backend/app/device_pairing_service.py:329-396`), и с ним доступны сканы, освобождение КИЗ и завершение заказов
Эту дыру станция не трогает и не расширяет; рекомендация отдельной задачей: ограничить выдачу ключа программы
теми же адресами склада

### 9. Проверки

Backend (`.venv/bin/python -m unittest discover -s tests` и `./tools/run_postgres_tests.sh all`):
- вход станции с адреса склада и отказ с чужого, без Origin, при пустом и битом списке; отказы не попадают
  в общий ограничитель; успешные входы упираются в свой предел
- сессия станции с чужого адреса отклоняется в `/api/v1/*` и в `/auth/check`, сессии других ролей не затронуты
- `/auth/check` и проксируемый запрос видят один и тот же адрес клиента (интеграционный тест с заголовками nginx)
- подделанный `X-Forwarded-For` от недоверенного соседа не даёт доступа
- парольный вход пользователем станции невозможен, пользователь создаётся один раз при гонке двух входов
- права роли `station` по матрице; правки: `tests/test_backend_rbac_policy.py` (роуты 70 на 71, набор ролей,
  решения 384 на 448, станция в наборе ограниченных ролей теста чувствительных поверхностей),
  `tests/test_postgres_rbac_audit.py` (`station: 64`)

Frontend (`npm run lint`, `typecheck`, `test`, `test:coverage`, `a11y`, `build`, `e2e --grep @smoke` в `frontend/`):
- правила скана общим корпусом с Python; паритет цветов, текстов и хешей блоклиста (раздел 3)
- загрузка `/` во всех ветках раздела 1, включая сеть недоступна и 429; моки msw (`src/__tests__/server.ts`,
  `src/test/server.ts`), e2e (`e2e/synthetic-api.ts`) и сервер производительности получают `/api/v1/auth/station`
- `tests/test_frontend_csrf_contract.py` остаётся зелёным: счётчики `csrfToken` в `App.tsx` и `AdminWorkspace.tsx` не уменьшаются
- лист печати: координаты и переносы по таблицам описи на всех четырёх размерах; число страниц PDF из Chrome
  равно расчёту `tests/test_printing.py`, без лишней пустой страницы
- офлайн: скан и завершение в очереди, досылка после связи, новая сессия после 401 не чаще раза в 30 с,
  одна станция на браузер (Web Locks)
- отдельный проект Playwright с включённым service worker: открытие без сети, обновление версии, `/admin` не перехватывается
- e2e на синтетическом API: скан, отмена, следующая позиция, завершение с печатью, возврат, закрытие смены
- бюджеты `frontend/performance-budgets.json`: доступность Lighthouse 1 на `/` палитра программы не пройдёт
  (белый на `#b28224` около 3,4:1); для станции заводится исключение с обоснованием «копия программы»,
  остальные бюджеты держатся

Внешний вид: снимки Playwright станции в области `1250x780` рядом со снимками со складского ПК, одобрение Антона

Живая проверка после выкатки backend этапа 1, только чтение:
- `POST /api/v1/auth/station` с машины агента даёт 403, с подделанным `X-Forwarded-For` адресом склада тоже 403
- положительный путь до склада: по разрешению Антона адрес агента на время проверки вносится в список,
  вход через nginx даёт 200 и рабочую сессию, затем адрес убирается
- вход со склада проверяется первым открытием ярлыка

Клиентский контракт `CLAUDE.md`: станция это новый веб-интерфейс, поэтому до выкатки каждого этапа на склад
показываются снимки «было (программа) и стало (сайт)» и запрашивается одобрение; Telegram-сообщения
и отчёты не меняются, no-send проверка не требуется

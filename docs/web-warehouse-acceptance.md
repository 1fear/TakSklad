# Приёмка web-склада: operator `/` и admin `/admin`

Дата: 2026-07-27.

Этот runbook разделяет локальные автоматические проверки, физическую приёмку на
складе и live-проверку после отдельного разрешения на deploy. Один слой не является
доказательством другого.

## Контракт

- `/` — операторский контур: выбор заказа и позиции, сканирование КИЗов,
  отмена последнего скана, завершение заказа, полный возврат и браузерная печать.
- `/admin` — административный контур с вкладками, доступными по permissions.
- Browser API работает через same-origin `/api` и web-сессию.
- `GET /api/v1/kiz/availability` — предварительная подсказка. Авторитетный результат
  записи даёт только `POST /api/v1/scans`.
- В web-контуре нет offline-очереди мутаций. При недоступном backend код остаётся
  в поле для повторной проверки, а действие завершается ошибкой.
- Печать запускается только явной кнопкой `Печать`; автоматической и «тихой»
  отправки на принтер нет.
- Возврат только полный: все позиции заказа подтверждаются одним действием.

## A. Локальные synthetic-гейты

Production, внешние API и реальные данные использовать нельзя.

| Проверка | Команда | Ожидаемый результат |
|---|---|---|
| Lint | `npm --prefix frontend run lint` | `PASS`, 0 warnings |
| TypeScript | `npm --prefix frontend run typecheck` | `PASS` |
| Unit/integration | `npm --prefix frontend run test` | Все тесты `PASS` |
| Coverage | `npm --prefix frontend run test:coverage` | Порог проекта выполнен |
| Accessibility | `npm --prefix frontend run a11y` | Все a11y-тесты `PASS` |
| Production build | `npm --prefix frontend run build` | `PASS` |
| Synthetic browser flow | `npm --prefix frontend run e2e` | Все smoke-тесты `PASS`; perf может быть skipped |
| Performance profile | `npm --prefix frontend run perf` | Bundle, Lighthouse и browser budgets `PASS` |

Synthetic browser flow обязан подтвердить:

1. `/` открывает операторский, а `/admin` — административный контур.
2. Ввод КИЗа не вызывает повторный `GET /orders/active` на каждый символ.
3. Scan выполняет preflight, затем authoritative POST и сверяет возвращённый код.
4. При отказе backend код не очищается и фокус возвращается в сканер.
5. Последний КИЗ отменяется только после подтверждения.
6. Завершение доступно только после всех обязательных КИЗов.
7. Модальное окно печати не вызывает `window.print()` до кнопки `Печать`.
8. Возврат отправляет полный набор позиций.
9. Synthetic smoke не выполняет внешних сетевых запросов.

Итог секции A: `PASS` только при зелёных командах; иначе `FAIL`.

## B. Физическая операторская приёмка

До выполнения на рабочем месте склада статус: `NOT RUN`.

Предусловия:

- согласованное тестовое окно и тестовый заказ;
- операторская учётная запись с `warehouse:read` и, для мутаций,
  `warehouse:write`;
- реальный сканер и принтер;
- согласованный rollback/stop condition для тестовых данных.

Сценарий:

1. Открыть `/`, войти операторской учётной записью.
2. Выбрать тестовый заказ и позицию.
3. Отсканировать валидный КИЗ аппаратным сканером и проверить очистку поля,
   прогресс и возврат фокуса.
4. Повторить тот же КИЗ: новая запись не должна появиться.
5. Проверить ошибочный/занятый КИЗ: значение должно остаться в поле, завершение
   позиции не должно измениться.
6. Отменить последний валидный КИЗ и подтвердить обратное движение в UI/аудите.
7. Досканировать обязательные позиции и нажать `Завершить заказ`.
8. В открывшемся окне нажать `Печать`, выбрать физический принтер и сверить лист.
9. По согласованному завершённому заказу найти возврат через поле
   `Номер или ID SkladBot, либо ID заказа`, нажать `Найти`, затем
   `Подтвердить полный возврат`.
10. Сверить, что возвращённые КИЗы снова доступны по штатному backend-контракту.

Stop condition: любой дубль, потеря введённого КИЗа, неверный товар/заказ,
неожиданная автопечать или расхождение аудита. Итог — `FAIL`, дальнейшие мутации
остановить.

## C. Live/deploy smoke

В этой локальной задаче статус: `NOT RUN`.

После отдельного разрешения и deploy нужно сверить точную runtime identity,
`/health`, `/version`, `/ready`, web-сессию и обе поверхности. Исторический
read-only probe не доказывает текущее состояние нового кандидата.
